# localcode

**Free, local, open-source coding-interview practice.** About 4,100 problems, with 2,800+ that can be run against hidden test suites. You get company-tagged frequency lists for 400+ companies, and reference solutions with explanations. You can write and judge solutions in **Python, Java, C++ and Kotlin**.

Everything runs on your own machine with Docker. There are no accounts and no subscription, and nothing is sent anywhere after the one-time download of the problem data. Every user judges against the same pinned compilers and runtimes, so a solution that passes for you passes for everyone.

> localcode is an independent project. It is not affiliated with, or endorsed by, LeetCode.

## Quick start

You need [Docker](https://docs.docker.com/get-docker/) with Compose v2.

```bash
git clone https://github.com/<you>/localcode.git
cd localcode
docker compose up -d --build
```

Open **http://localhost:4173**. On first launch localcode downloads and indexes the open datasets, which is about 200 MB and takes a few minutes. Your progress is stored in the `localcode-data` Docker volume.

To stop it, run `docker compose down`. Your data is kept. To update the problem data later, use **Progress → Check for updates**.

## Features

- **Problem list**: search, difficulty, status and topic filters, and ⌘K to jump to a problem.
- **Company lists**: pick from 400+ companies, sort by frequency, and switch between 30 days, 3 months, 6 months and all time. Each company page shows its difficulty and topic mix, your progress, and "practice next unsolved".
- **Workspace**: a Monaco editor with drafts autosaved per language. **Run** (⌘↵) checks the examples plus your own custom cases. **Submit** (⌘⇧↵) runs the full hidden suite and reports the verdict, the first failing case, runtime and memory.
- **Reference solutions**: several approaches per problem, with explanations and complexity, and an "open in editor" button.
- **Submission history**, a **progress dashboard** (solved over time, by topic, by company) and JSON export.
- Dark and light themes.

## How it works

```
 browser ──► app (FastAPI + React)  ──────────►  runner (sandboxed toolchains)
             · importer → content.db              · Python 3.12, JDK 21, g++ 14, Kotlin 2.0
             · user.db (your progress)            · non-root, no network, CPU/memory/time limits
             · judges results                     · executes code, returns raw per-case results
```

- **Content is imported, not shipped.** The importer pulls from three open-source projects (below), merges them by problem slug, and builds `content.db`. Re-importing never touches `user.db`.
- **Tests are language-neutral.** Each case is stored as JSON arguments plus an expected value. Small per-language harnesses turn those into typed calls: Python by its type hints, Java and Kotlin by reflection, C++ through a generated `main`. Comparison happens in the app, never in user code.
- **The runner has no internet access.** It sits on an `internal` Docker network. Each submission runs as an unprivileged user in a throwaway directory with time, memory and process limits.
- **Test data is cleaned up.** The upstream cases were generated by running Python on synthetic inputs, and some of them break the problems' own constraints (for example 64-bit values where the problem promises 32-bit ones). The importer drops cases the typed languages can't represent. It also applies a shipped exclusion list ([`backend/localcode/data/excluded_cases.json`](backend/localcode/data/excluded_cases.json)), produced by running the Java and C++ reference solutions over every suite.

See [docs/architecture.md](docs/architecture.md) for more detail.

### Mirrors

If an upstream source goes away, point the importer at a mirror. Each variable takes a comma-separated list, tried after the default:

```bash
LOCALCODE_DATASET_MIRRORS=https://example.com/datasets/LeetCodeDataset \
LOCALCODE_DOOCS_MIRRORS=https://github.com/<you>/leetcode.git \
LOCALCODE_COMPANIES_MIRRORS=https://github.com/<you>/leetcode-company-wise-problems.git \
docker compose up -d
```

## Known limitations

- **Kotlin reference solutions are sparse** upstream, so the Solutions tab shows Java for Kotlin when needed. Kotlin submissions are judged normally.
- **Problems with several valid answers** (for example "return any valid arrangement") are compared against one expected answer, except where the statement says "in any order", which is compared without regard to order.
- **Design, SQL, shell and concurrency problems** can be read but not run.
- **Cold compile time**: Java takes about 1 s, C++ about 1 s and Kotlin about 4 s per Run or Submit.
